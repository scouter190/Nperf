# 001 - Tareas

- [x] T1 Esqueleto de punta a punta: `go.mod` (módulo `nperf`), `server` y `client` conectan por el canal de control (`hello` → `params` → `start` → `result`) y miden 1 flujo TCP `fwd` (cmd/nperf, internal/proto, internal/server, internal/client, internal/meter/tcp.go) — `go test ./...` con un test de integración en loopback que obtiene throughput > 0; `go run ./cmd/nperf server` y `client 127.0.0.1` imprimen Mbps.
- [ ] T2 Medidor UDP: ritmo de envío por bytes adeudados, secuencia y hora de envío, jitter RFC 3550, pérdida; envoltura de pruebas que descarta paquetes (internal/meter/udp.go) — test en loopback: 50 Mbps ±5 % durante 2 s; con 10 % descartado, pérdida reportada 10 ±1 puntos.
- [ ] T3 Compilación cruzada: `scripts/build-windows.sh` (GOOS=windows GOARCH=amd64) — `GOOS=windows go vet ./...` y el script producen `nperf.exe` sin errores.
- [ ] T4 UDP en la sesión: `-proto udp`, `-udp-rate` (acepta `50M`, `1G`), 100 Mbps por defecto sin TCP previo, saludo UDP en el puerto 5300 (internal/client, internal/server, cmd/nperf) — test de integración: `-udp-rate 50M` envía 50 Mbps ±5 %; sin la flag, 100 Mbps ±5 %.
- [ ] T5 Autenticación y versión: HMAC con nonce, regla de versión mayor (internal/auth, internal/version, internal/proto) — tests: clave errónea da "clave incorrecta" y código ≠ 0 sin carga; un proxy de prueba no ve la clave en los bytes del canal de control; versión mayor distinta da aviso en ambos lados.
- [ ] T6 Sentidos `rev` y `both`, con "no medido" (internal/client, internal/server, internal/meter) — tests: `rev` mide B → A; `-direction fwd` reporta rev como "no medido" y viceversa.
- [ ] T7 Flujos paralelos `-streams` con suma (internal/meter/tcp.go) — test: con 8 flujos el servidor acepta 8 conexiones de datos y el total es la suma de los parciales.
- [ ] T8 Secuencia completa por defecto: RTT por el canal de control, luego TCP y UDP al 90 % del TCP del mismo sentido (internal/client) — test: el orden de resultados es RTT, TCP fwd, TCP rev, UDP fwd, UDP rev; la tasa UDP es 90 % ±5 % del TCP.
- [ ] T9 Retransmisiones por SO con build tags (internal/tcpinfo) — test en Linux que lee TCP_INFO de un socket real; `GOOS=windows go build ./...` compila; sin soporte se reporta "no disponible".
- [ ] T10 Cola: máximo 5 en espera, posiciones, "cola llena" al 6.º, cancelación al cerrar la conexión (internal/server, internal/client) — test con 7 clientes y sesiones lentas: posiciones 1–5, el 7.º rechazado con código ≠ 0, cancelar el 2.º hace avanzar a los demás; test de Ctrl+C con cancelación por contexto.
- [ ] T11 CLI completa: `-port` 5300, `-key` o config, `-duration` 3–300 (default 10), validación antes de conectar, códigos de salida (cmd/nperf, internal/config) — tests: `-duration 2` y `-duration 301` fallan sin conectar; con `-duration 3` en loopback, cada fase dura 3 s ±0,5 s.
- [ ] T12 Salida en texto y `-json` (internal/report, cmd/nperf) — test con golden file: el JSON es válido y trae todas las métricas, sentidos, protocolos y "no medido" / "no disponible".
- [ ] T13 Prueba de aceptación en loopback con valores por defecto, criterio 1 (cmd/nperf/e2e_test.go) — `go test ./cmd/nperf -run E2E` compila el binario, levanta `server` y `client`, y el cliente termina con código 0.
